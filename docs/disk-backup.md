# Зашифрованные копии на обычном Яндекс Диске

VPS хранит публичный ключ age и отдельное подключение rclone к папке приложения
на Диске владельца. Архив содержит штатный манифест, SQLite и зарегистрированные
медиа, а также исходный пакет промптов, если он включён штатным backup. Ключи
Telegram и OpenAI, весь внешний vault, SSH-ключи и учётные данные rclone требуют
отдельного хранения. Дешифрование возможно на ПК с закрытым ключом.

## Однократное подключение

1. На ПК в защищённой папке создайте ключ командой
   `age-keygen -o age-identity.txt`. Сохраните закрытый ключ в менеджере паролей
   и ещё одну доступную для восстановления копию вне VPS и Диска. Публичный
   ключ выводит `age-keygen -y age-identity.txt`. На VPS запишите **только одну
   строку `age1…`** в `/etc/zarya-cd/age-recipient`, root:root, 0600.
   Старые закрытые ключи нужны до истечения срока хранения их архивов.
2. Установите age и rclone с поддержкой параметра `--yandex-app-folder`
   на ПК и VPS (rclone 1.76.0 или новее). Проверьте официальную контрольную
   сумму дистрибутива. Проверка возможности на сервере:
   `rclone help backend yandex`. [Официальные сборки](https://rclone.org/downloads/)
3. Зарегистрируйте собственное приложение Яндекс OAuth, выберите разрешение
   `cloud_api:disk.app_folder` и callback `http://127.0.0.1:53682/`.
   На ПК запустите `rclone config --config zarya-disk.conf`, создайте
   подключение **zarya-disk**, тип **yandex**, введите Client ID/Secret своего
   приложения и включите `app_folder=true` в расширенных параметрах. Подтвердите
   доступ в браузере. Область доступа определяет выданный токен.
   [Настройка папки приложения](https://rclone.org/yandex/#application-folder)
4. По защищённому каналу передайте на VPS только изолированный конфиг rclone.
   Каталог `/var/lib/zarya-backup` должен принадлежать `zarya-svc:zarya-svc`,
   режим 0700. Файл `/var/lib/zarya-backup/rclone.conf` — тот же владелец, 0600.
   rclone может обновлять OAuth-токен в этом файле. Секреты вводите локально.
5. Выполните `sudo sh deploy/install.sh` по руководству CD. Для существующей
   установки предварительно остановите активные таймеры и дождитесь завершения
   обоих oneshot. Состояние уже выбранного релиза сохраняется.
   Запустите `sudo systemctl start zarya-backup.service`. Служба создаёт первую
   копию в любое время при свободной очереди. Имя подтверждённого объекта видно
   в `journalctl -u zarya-backup.service`. Выполните проверку восстановления ниже,
   затем включите оба таймера. [Подключение CD](pull-deployment.md)

## Расписание и ошибки

* Ночной таймер проверяет состояние каждый час на 17-й минуте UTC. После
  03:00 UTC создаётся один согласованный снимок за дату UTC. Если Заря занята,
  попытка откладывается. Остановка длится до завершения локального backup.
  Ранее работавшая Заря запускается **до шифрования и передачи по сети**.
  Снимок остановленной владельцем службы сохраняет её состояние остановки.
* Локальная очередь `/var/lib/zarya-cd/nightly` переживает перезапуск и сетевые
  сбои. Повтор использует тот же идентификатор и подготовленный шифротекст.
  Ночной и предрелизный процессы берут общий `deploy.lock`. Фазы журнала
  позволяют вернуть службу после прерывания во время создания локальной копии.
* При деплое перед остановкой проверяется доступ к каталогу на Диске. После
  остановки отправляется **точный предмиграционный снимок**. Только подтверждение
  SHA-256 удалённых байтов допускает миграцию. Ошибка квоты, доступа или сети
  возвращает старую версию с исходной БД. После сбоя передачи действует часовая
  пауза; следующая попытка снимет новое состояние. Уже доставленные архивы
  адресуются по уникальному имени с SHA-256.
* Объекты находятся в папке приложения под `Zarya/v1/nightly` и
  `Zarya/v1/predeploy`. Перед обработкой очереди обслуживаются сроки
  хранения: ночные за последние 30 дней (как минимум последний), предрелизные —
  последние 10. Для освобождения квоты удаляются окончательно только объекты
  распознанного формата в этих двух каталогах и незавершённые временные объекты
  прежних предрелизных попыток. Общая корзина Диска не очищается.
  При заполнении хранилища проверьте квоту и журнал. Недоставленные локальные
  снимки остаются в очереди; недостаток локального места откладывает новый снимок.
* Локальные предрелизные backup в `/var/lib/zarya-cd/runs` подчиняются отдельной
  политике хранения VPS. Проверяйте свободное место на обоих носителях.

## Проверка восстановления на ПК

Скачайте конечный `.tar.gz.age` из папки приложения через интерфейс Диска или
`rclone copyto`. По возможности выбирайте версию Зари, соответствующую схеме
снимка. На ПК с age в PATH, рабочим окружением Зари и отдельным приватным
каталогом для временных и восстановленных данных выполните:

```powershell
.venv/Scripts/python.exe deploy/restore_disk.py backup.tar.gz.age age-identity.txt private/restore-test
```

Родительский каталог должен существовать, целевой — быть новым. Должно хватить
места для расшифрованного архива, распаковки и проверенного восстановления.
Инструмент проверяет расшифровку, пути, штатный манифест, контрольные суммы,
схему SQLite, целостность и связи медиа. Успехом считается новый каталог с
`restore-quarantine.json`. Приложение и Telegram при этом не запускаются. В
рабочем журнале VPS можно проверить доставку шифротекста; подтверждение
восстановимости требует отдельной проверки с ключом владельца на ПК.
