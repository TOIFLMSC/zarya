# Конфигурация

## Где хранится

| Что | Источник | Как менять |
| --- | --- | --- |
| Характер, имя, тон, владелец, модели и лимиты | data/zarya.sqlite3 | Настройки Web UI |
| Реакции, выразительность, режим/шанс инициативы | SQLite | Поведение |
| Режим подбора долговременной памяти, включая E5 | SQLite | Настройки → Память |
| Последних человеческих сообщений на собеседника | SQLite | Настройки → Память |
| Разрешения, память, журнал | SQLite и media-файлы в data | Соответствующие разделы UI |
| Полные инструкции всех модельных маршрутов | Выпуски конфигурации в SQLite | Настройки → Промпты Зари |
| Ключи API | Файлы в data либо окружение | Локально, затем перезапуск |
| Пути, порт, медиабинарники | Окружение | .env.example описывает имена |

`ZARYA_DATA_DIR` переносит всё хранилище; `ZARYA_PROMPTS_FILE` задаёт приватный
файл инструкций для первого импорта. Любые каталоги за пределами проекта защищайте отдельно:
.gitignore действует только в своём репозитории. `ZARYA_WEB_DIR` задаёт сборку UI,
`ZARYA_PORT` — локальный порт. `ZARYA_DEV_UI=1` отключает реальные интеграции
и разрешает локальный Vite origin для разработки.

## Пакет промптов

JSON с `schema_version: 1` и объектом `fragments`. Полный набор ключей задан
в нейтральном `src/zarya/prompts.example.json`: dialogue.*, links.*, behavior.plan,
memory.extract, research.analyse, media.*. Значения — текст, не Python/Jinja:
скобки и выражения не исполняются. Динамические имя, persona и тон подставляет
сам код в фиксированных местах. Не удаляйте обязательные ключи.

Пакет ограничен 128 КиБ, фрагмент — 32768 символов. Повторные/неизвестные ключи,
неверная версия и типы отклоняются. Первый CLI-запуск требует локальный файл;
отсутствие или ошибка не подменяются публичным примером. Программный Config без
prompts_file использует нейтральный пакет для тестовых/встроенных установок.

Миграция 019 импортирует текущие настройки и пакет до запуска клиентов. После
этого SQLite хранит неизменяемые выпуски; правка `prompts.json` и перезапуск
больше не меняют рабочие инструкции. Каждый выпуск содержит полный пакет и
настройки. Сохранение формы UI также создаёт выпуск с прежними инструкциями.

Активация применяется к новым операциям без рестарта; задания, уже привязанные
к версии, используют её пакет. Сохранённый replay не вызывает модель; платный
replay использует текущий выпуск с повторной проверкой версии. Старые версии
настроек до миграции получают совместимый пакет первого импорта, а не якобы
сохранённые исторические промпты; они не предлагаются для отката.
База и снимки запросов приватны.

## Редактор промптов и выпуски

В «Настройки» → «Промпты Зари» откройте редактор и выберите нужный фрагмент.
Можно изменить несколько фрагментов и сохранить их одним черновиком. Сохранённый
черновик лежит в SQLite и доступен после перезагрузки страницы. До активации
новые операции продолжают использовать активный выпуск. Редактор работает при
выключенном мосте Obsidian.

Откройте «Сравнить изменения», проверьте изменённые фрагменты, подтвердите
просмотр и активируйте выпуск. Правка промптов сохраняет параметры, действовавшие
в его основе. Если выпуск изменился в другой вкладке или при сохранении обычных
настроек, устаревший черновик остаётся доступен для просмотра. В новый черновик
текст переносится вручную. Размеры и ключи проверяются при сохранении.

В «Истории выпусков» можно подготовить откат к выбранной версии. Сравнение
показывает прежние настройки и промпты, которые будут восстановлены. После
подтверждения откат создаёт следующий выпуск. Уже отменённые задания и
удалённые данные не восстанавливаются.

G6 добавляет `memory_retrieval`: по умолчанию `shadow`. Новый подбор сравнивается
локально с прежним, сохраняя прежний вход модели. Для включения в ответы выберите
`graph`. Диагностика и ограничения описаны в [memory-retrieval.md](memory-retrieval.md).

`participant_context_messages` задаёт персональное окно: целое число 1–100,
по умолчанию 20, включая текущее человеческое сообщение. Связанные отправленные
ответы Зари не занимают эту квоту. Настройка работает независимо от фоновой памяти
и применяется к новым запросам без перезапуска. Старые выпуски без поля читаются
с пределом 20 без изменения сохранённых байтов. В Obsidian поле входит в заметку
«Модели и лимиты». Для просмотра окна выберите человека в «Памяти»; фактический
состав конкретного запроса сохранён в «Диалогах».

Серии сообщений включены по умолчанию в разрешённых группах. Переключатель
«Серии сообщений» находится в карточке группы в «Telegram и доступ → Группы».
Настройка применяется к новым репликам сразу. Выключение сохраняет доставку
уже собранных серий. При повторном одобрении группы выбор сохраняется.

`topic_context_chat_id` включает пилот хронологии для одной одобренной
форумной группы. В «Настройки → Память» укажите отрицательный ID чата из
раздела доступа. Пустое поле выключает режим для новых запросов сразу после
сохранения. В старых версиях настроек и заметках Obsidian без поля пилот
выключен. Работает без фоновой памяти. Записи сохранённых ответов по-прежнему
доступны, пока действительны доступ и все их источники.

`participant_summaries_enabled` включает персональные фоновые сводки (по умолчанию
включены, требуют включённой фоновой памяти). В «Памяти» видны блоки, исходники,
покрытие окна, состояния и отдельный расход. Модель — `memory_model`, reasoning low.
Диалог использует готовые блоки и не ждёт обработки. При выключении новые запросы
получают оригиналы; уже готовые блоки не пересоздаются при смене настройки или модели.

`participant_summary_prompt` — отдельная локальная инструкция саммаризации, доступна
в настройках памяти и конфигурационной заметке «Модели и лимиты». Публичный default
является нейтральным техническим примером. Действующие характер и пакет промптов
не переписываются. Старые неизменяемые выпуски без двух новых полей читаются с defaults;
сохранённые байты и хеши выпусков остаются прежними.

`max_output_tokens` также резервируется при проверке вместимости окончательного
диалога; этот выходной предел уже включает рассуждения. При переполнении личное окно
N, выбранные реплаи и факты не обрезаются автоматически. В «Диалогах» → «Подробности»
→ «Контекст» доступен блок «Вместимость контекста» с составом запроса, исключениями,
приблизительной оценкой и отдельным подсчётом API, если он понадобился. Оценка
не заменяет фактический usage в «Модель и расход». Лимиты поддерживаемых моделей
версионированы в коде по документации провайдера; текущие настройки и промпты
установки при добавлении этой проверки не переписываются.

Схемы ответа, права доступа, разделение памяти, ограничения файлов, сетевые
проверки и правила очередей остаются кодом. Текст промпта не заменяет эти проверки.
Публичные значения по умолчанию — пример новой установки, а не экспорт настроек
какого-либо работающего бота. Старые версии настроек в существующей БД сохраняются.

## Локальный мост Obsidian

Для памяти можно создать приватный `data/obsidian.local.json`:

```json
{
  "enabled": true,
  "project_path": "C:/Users/USER/Documents/Obsidian/Vault/Projects/Zarya"
}
```

Папка проекта должна существовать. Приложение создаёт в ней управляемые
подпапки `Память Зари` и `Конфигурация Зари`, проверяет привязку и не импортирует соседние заметки.
Группы и одобренные лички экспортируются отдельно. Путь и экспорт приватны;
файл конфигурации находится в игнорируемом каталоге данных. После изменения
конфигурации перезапустите приложение. `enabled: false` отключает файловый мост.

Путь должен быть доступен на машине, где работает Заря. На VPS конфигурация
читается из каталога данных службы. SSH-туннель к панели открывает Web UI,
а папку Obsidian на Windows нужно связать с VPS отдельно. При переносе
сохраните маркеры обеих управляемых папок и проверьте файлы по реестру рабочей
SQLite. Старая папка может содержать снятые с публикации заметки, которые
не должны попадать в новую синхронизацию. Если база хранит привязку к прежнему
пути, потребуется контролируемая перепривязка с сохранением реестров.
Мост Obsidian работает независимо от выбранного режима поиска памяти.

Редактирование существующего факта в Obsidian создаёт предложение в разделе
«Память» Web UI. Оно применяется только решением владельца с проверкой версии;
источники и эпизоды доступны для чтения. Промпты и характер находятся отдельно
в `Конфигурация Зари`: четыре заметки настроек и папка `Инструкции` с фрагментами
промптов. `Начало.md` связывает заметки для просмотра в графе Obsidian.

## Правки конфигурации через Obsidian

1. Меняйте только содержимое блока в существующей управляемой заметке.
   В JSON сохраняйте все поля и их типы; не меняйте заголовок, версию и ограждение блока.
2. Дождитесь двух одинаковых проверок полного комплекта (обычно до 30 секунд).
   Кнопка «Проверить правки из Obsidian» запускает одну проверку вручную.
3. В «Настройки» → «Промпты Зари» откройте черновик. Сравнение
   показывает исходный текст, текущую версию и предлагаемый текст каждого изменённого узла.
4. Подтвердите просмотр и активируйте выпуск либо отклоните черновик.
   До активации Заря продолжает использовать прежнюю конфигурацию.

Перед активацией проверяются версия базы и точные байты всех заметок; настройки,
инструкции и необходимые отмены заданий фиксируются одной SQL-транзакцией.
Изменение файлов во время проверки, неполный комплект, чужой маркер или неверный
JSON блокируют применение. Конфликт не объединяется автоматически: сохраните
свою правку отдельно, отклоните черновик, обновите синхронизацию и повторите правку.
Удаление файла не удаляет конфигурацию и не пересоздаёт готовую заметку автоматически.

В истории «Подготовить откат» создаёт черновик предыдущего выпуска. Он требует
такого же просмотра и активации, создаёт новую версию и не возвращает отменённые
задания. Ключи API, права чатов, настроение и режим/шанс инициативы отдельных
групп сюда не входят. Эти параметры остаются в своих разделах UI или локальных файлах.
Obsidian не должен быть открыт для работы бота; доставка Sync на другие устройства
зависит от настройки и доступности Sync.
