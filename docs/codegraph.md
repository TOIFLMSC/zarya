# CodeGraph для разработки

CodeGraph помогает находить символы, зависимости и затрагиваемые тесты в текущем
рабочем дереве. Он работает отдельной командой Python, без запуска Зари,
SQLite, API-ключей, платных моделей и новых зависимостей.

## Команды

Выполняйте из корня проекта с установленным окружением:

```powershell
uv run --frozen python -m zarya.codegraph build
uv run --frozen python -m zarya.codegraph --read-only status
uv run --frozen python -m zarya.codegraph --read-only --limit 10 search MemoryEngine.context
uv run --frozen python -m zarya.codegraph --read-only show select_episodes
uv run --frozen python -m zarya.codegraph --read-only impact src/zarya/memory_context.py --depth 3
```

`search` ищет по имени символа или пути. `show` возвращает символ и ближайшие
связи; при неоднозначном запросе сначала выберите конкретный `id` из `search`.
`impact` проходит по обратным импортам файлов и предлагает тесты с цепочками
зависимостей. Пустой список не означает, что тесты не нужны. `--limit` задаёт
1–200 результатов, `--depth` для impact — 1–8 переходов.

По умолчанию каждая команда сохраняет индекс в `data/codegraph/index.json`.
С `--read-only` граф строится в памяти: файлов, блокировок и кэша не создаётся.
`export` несовместим с этим режимом. `--root` позволяет явно указать корень
исходников; остальные пути в графе относительные.

## Свежесть и покрытие

Каждый запрос заново перечисляет разрешённые файлы и хеширует их байты,
включая новые, удалённые и незакоммиченные изменения. Из этих же байтов строится
граф. После разбора набор и хеши проверяются повторно; при изменениях выполняется
до трёх попыток. Старый индекс не используется как ответ при ошибке.

Вывод содержит `snapshot_id`, версии схемы/извлекателя/политики, хеши файлов,
места определений и происхождение связей. Проверяйте `diagnostics`, `truncated`,
`depth_limited` и `unresolved_total`. `complete: true` означает отсутствие ошибок
разбора разрешённых файлов; полноту всех runtime-связей это не доказывает.
Непрерывные правки, ссылки файловой системы или превышение лимитов прерывают запрос.

Python разбирается через AST: модули, классы, функции, методы, тесты, импорты,
наследование и простые вызовы с однозначным лексическим/import binding.
Переопределения, условные привязки и неизвестные объекты не получают точных
связей вызова. `self.method()` отмечается как `calls_candidate`, а не как
подтверждённый runtime-вызов. Lambda/comprehension, декораторы, defaults,
аннотации, monkey patching и динамическая диспетчеризация не покрываются полностью.

Для TypeScript/JavaScript извлекаются экспортируемые имена и подсказки относительных
импортов (`import_hint`). CSS представлен файлами. Из SQL-миграций берутся
объявления, изменения и ссылки таблиц; SQL из runtime-строк не извлекается.
Из документов берутся только ссылки на индексируемые файлы, без пересказа текста.

Текущие пределы: 512 файлов, 1 МиБ на файл, 16 МиБ исходников и 32 МБ графа.
Список неопределённых мест ограничен 200 записями с отдельным общим счётчиком.
Это ограниченная карта проекта; для существенно большего репозитория потребуется
пересмотреть лимиты и способ индексации.

## Использование агентами

Перед изменением нескольких файлов основной агент ищет точки входа через
`search`/`show`, оценивает соседние файлы и кандидаты тестов через `impact`, затем
проверяет решающие определения и вызовы в исходниках. После изменения запросы
повторяются: граф сам учитывает новые байты, отдельный watcher не нужен.

Специалисты получают ограниченную задачу и используют только `--read-only`.
Результат содержит `snapshot_id`, пути/строки и указание неопределённости.
Если роль запрещает shell, основной агент передаёт ей уже полученный вывод.
Граф сокращает поиск; тесты и чтение кода остаются частью проверки.

## Экспорт в Obsidian

Укажите новую управляемую подпапку с точным именем `CodeGraph Зари`:

```powershell
uv run --frozen python -m zarya.codegraph export --output 'C:\path\to\vault\CodeGraph Зари'
```

Родительская папка должна существовать и находиться вне исходников. Экспорт
создаёт `Начало.md`, связанные заметки модулей и структурный `graph.json`.
Папка отделена от мостов памяти и конфигурации. Её можно просматривать в
Obsidian; редактирование карты не меняет код. Автоматический экспорт и проверка
доставки Obsidian Sync не реализованы: повторите команду после правок.

Служебный маркер связывает папку с текущим корнем проекта и хешами управляемых
файлов. Повторный экспорт обновляет и удаляет только свои неизменённые заметки,
сохраняет посторонние файлы и останавливается при неизвестных/отредактированных
байтах. Прерванная запись восстанавливается по признанным хешам. Не удаляйте
маркер для обхода конфликта. После переноса исходников на другую машину создайте
новую папку экспорта; сам JSON использует относительные пути и пригоден для переноса.

## Границы данных

Разрешены Python в `src/zarya`, SQL в `src/zarya/migrations`, код тестов,
TypeScript/JavaScript/CSS в `web/src`, структура `scripts/check-publication.py`,
README и шесть публичных документов: setup, configuration, architecture,
privacy, operations, codegraph. Скрытые каталоги, assets и runtime-папки исключены.

Индекс и экспорт содержат только пути, идентификаторы, категории, позиции,
хеши и связи. В них нет тел функций, комментариев, docstrings, строковых значений,
текста промптов, диалогов и личной памяти. Исторические приватные документы,
AGENTS.md, `.codex`, data, резервные копии и Obsidian не индексируются.
CodeGraph не запускает публикационный аудит и не читает его приватные входы.
Проверка перед коммитом описана отдельно в [privacy.md](privacy.md).
