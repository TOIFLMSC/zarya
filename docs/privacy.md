# Приватные данные и публикация

В Git входят исходники, тесты с синтетическими данными, нейтральный пример
промптов, lock-файлы и эта документация. `.gitignore` исключает data, backups,
restore-checks, logs, окружения, сборки, результаты тестов, .env и локальные
agent-конфигурации. Исторические заметки конкретной установки исключены отдельно.

Приватны: SQLite/WAL/SHM, настройки и их версии, промпты, диалоги и снимки запросов,
профили/память, согласия/доступы, исходные медиа, диагностические выгрузки,
ключи и резервные копии. Резервная копия — не обезличенный экспорт.
Не помещайте реальные значения в .env.example, prompts.example.json, фикстуры,
скриншоты, issue или PR. При публичной демонстрации используйте отдельную пустую БД.

Перед коммитом:

```powershell
git status --short
git diff --cached --stat
uv run --frozen python scripts/check-publication.py
```

Проверка читает именно Git index, отклоняет неожиданные пути/базы/архивы и типичные
форматы ключей. Если data/prompts.json существует, ищет длинные частные фрагменты
в подготовленных текстах, включая экранированные Python/JSON-строки. Это дополнительная
проверка, а не математическая гарантия отсутствия всех секретов. Ручное ревью остаётся
необходимым. .gitignore не удаляет уже закоммиченные данные, а `git add -f` обходит его.
Если секрет попал в историю, сначала отзовите его; удаления из последнего коммита мало.

Клиенты Telegram/OpenAI получают данные, необходимые для выполнения запросов.
Локальное хранение не означает, что модель работает офлайн. Ограничивайте доступы
чатов и локальный доступ к панели и файлам по своей модели угроз.
