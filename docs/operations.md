# Эксплуатация и проверка

Запускайте один экземпляр и один Uvicorn worker без reload. Блокировка каталога
данных защищает от второго процесса с тем же хранилищем; не запускайте другого
получателя с тем же Telegram-токеном на другой машине.

В UI доступны доступы, диалоги/доставка, память, интернет, общая лента медиа,
поведение и пилотные метрики. Расход может быть неизвестен: отсутствие цены
не означает бесплатный вызов. Платный replay требует явного действия.

## Проверки

```powershell
uv run --frozen ruff check src tests scripts
uv run --frozen mypy
uv run --frozen pytest -q
Set-Location web
pnpm run build
```

`tests/browser-smoke.cjs` — отдельная браузерная проверка с временной БД и
синтетическими адаптерами. Нужен Playwright; путь к модулю можно задать через
ZARYA_PLAYWRIGHT_MODULE. Не направляйте этот сценарий на рабочую базу.
Python-тесты и сборка не подтверждают визуальную проверку и живое качество бота.

## Резервные копии

Полностью остановите приложение. Затем:

```powershell
uv run --frozen python -m zarya.backup backup data backups/manual
uv run --frozen python -m zarya.backup verify backups/manual
uv run --frozen python -m zarya.backup restore backups/manual restore-checks/manual
```

Пути назначения должны быть новыми и вне источника. Используется SQLite backup,
а не копирование одиночного файла работающей WAL-базы. В копию входят БД,
упомянутые в ней фото/кадры и data/prompts.json, если он существует. API-ключи,
логи и ненужные временные файлы исключены. Если ZARYA_PROMPTS_FILE указывает за
пределы data, сохраните этот файл отдельно в приватном хранилище. Копии предыдущего
формата без промптов проверяются, но для запуска понадобится собственный пакет.

Restore создаёт карантин: приложение откажется стартовать с такой копией.
Не удаляйте маркер ради автоматического запуска старых прав, очередей и заданий.
Это проверка восстановления, а не автоматический failover. Перенос на VPS
потребует отдельного контролируемого плана с остановкой локального получателя.

Секреты и копии храните отдельно от Git. Политика удаления рабочей базы не очищает
ранее сделанные резервные копии.
