# Подключение команды разработки

Открой [инструкцию к комплекту](assets/dev-agent-team/README.md). Определи
целевой репозиторий, прочитай применимые AGENTS.md, README, манифесты и CI.
Выбери `ui`, когда интерфейс входит в обычную разработку проекта. В остальных
случаях используй `backend`. Для повторной установки учитывай настройки
`.codex/dev-team.toml`.

Вызови `python assets/dev-agent-team/install.py <project> --profile <backend|ui>`
с абсолютным путём к скрипту из скилла. Просмотри diff. Если пользователь
попросил подключить команду, запусти ту же команду с `--apply`, затем `--check`.
При конфликте объясни, какой локальный файл или блок его вызвал, и сохрани
написанные в проекте правила. Настраивай состав, модели и reasoning через
`.codex/dev-team.toml`. Проверки стека и команды запуска возьми из проекта.

В свежей доверенной сессии проверь, что доступна нужная роль. Для простой
задачи достаточно основного агента. Для существенной правки проверь, что
ревьюер получает ограниченный diff и возвращает независимые замечания.
Для UI проверь присутствие дизайнера. Укажи отдельно, если удалось проверить
только файлы или загрузку профиля. Используй доступные в клиенте модели
и не выдавай изменение настройки проекта за переключение активного чата.
