# Подключение к Pull CI/CD

Открой [инструкцию и контракт адаптера](assets/pull-cd/README.md). Этот скилл
поставляется с той же версией Python-скриптов, примера workflow и Linux-проверки.
Для подключения перенеси их командой `python assets/pull-cd/scaffold.py <project>`
из каталога скилла. Для отдельного примера workflow можно передать
`--example-workflow`. Сохрани рабочие проверки и политику merge проекта.

Установи фактические команды CI, имя ветки, проверку готовности и способ остановки
писателей. Определи, где хранятся изменяемые данные и какие проверки подтверждают
согласованность снимка и миграции. Сопоставь это с контрактом `snapshot/migrate/verify/apply`.
Демо SQLite подходит как отправная точка для одного локального файла БД.
У внешнего хранилища проверь собственный метод согласованного backup и rollback.
Если адаптер устанавливает приложение из wheel или другого временного файла,
проверь, что запуск и откат используют установленный рантайм. После этого
можно разместить установщики в `install-inputs/` и включить
`prune_install_inputs` в конфигурации проекта.

В PR покажи, как корневой установщик и сервисный пользователь разделяют полномочия.
При подключении реального VPS используй scoped GitHub-токен, публичный age-ключ и
отдельную папку внешнего хранилища. Секреты владелец предоставляет через
защищённый локальный ввод. Скилл не расширяет разрешения на операции.

Рабочие критерии приёмки:

- Сборка для коммита релизной ветки проходит CI, и таймер забирает её сам.
- Ошибка до допуска возвращает прежнюю версию с контрольной записью.
- Ошибка после допуска сохраняет новые записи и удерживает сервис для разбора.
- После успешного деплоя и очередного опроса сохранены текущий и предыдущий
  рабочие релизы и один локальный предрелизный снимок. Если включена очистка
  установщиков, `install-inputs/` удалён и сохранённые релизы запускаются без него.
- Архив скачан из выбранного внешнего хранилища и восстановлен с ключом владельца
  в изолированное место. Шаблон использует маркер карантина.

До включения штатных таймеров заверши тест восстановления первой копии. В отчёте
различай стенд с фикстурой и фактический прогон на VPS. Укажи путь или коммит
версии шаблона в проекте и результат каждого применимого критерия.
