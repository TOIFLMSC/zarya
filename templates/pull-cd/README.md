# Pull CI/CD 0.1.0

Шаблон одного сервиса на Ubuntu 24.04 с GitHub Actions, systemd и Python 3.12.
Для сервиса выделяются пользователи приложения и контроллера, loopback-порт, каталог данных, пара
таймеров и отдельный префикс внешнего хранилища. В комплекте есть пример
приложения на SQLite и приёмка на отдельном тестовом сервисе.

## Как применить в другом репозитории

Из checkout исходника шаблона выполните команду с путём к существующему проекту.

```sh
python templates/pull-cd/scaffold.py /path/to/project --example-workflow
```

Файлы появляются в `deploy/pull-cd/`. Флаг кладёт пример workflow в
`.github/workflows/ci-pull.yml`. При существующем CI скопируйте файлы без флага
и добавьте упаковку и публикацию в проверенный workflow проекта. Команды
сборки в примере относятся к демо. Сверьте имя ветки, workflow и префикс
артефакта с `project.example.json`. В новый репозиторий коммитятся проверенные
файлы шаблона вместе с его `VERSION` и адаптером проекта.

На рабочем месте с установленным скиллом можно дать Codex задачу
`$pull-cd-onboarding Подключи шаблон к этому репозиторию`. Скилл содержит
автономную копию шаблона. Обновление в другом проекте идёт отдельным diff,
поэтому можно сохранить его адаптер и настройки.

## Контракт приложения

В `project.json` задайте имя проекта, источник GitHub, loopback-проверку,
частоту опроса, время проверки готовности и паузу после ошибки выгрузки.
Ночной таймер проверяет очередь каждый час в `:17` UTC и делает один снимок
за дату UTC. Хранятся последние N архивов каждого класса. Контроллер дописывает
имя проекта и класс снимка к пути `backup.remote`. В rclone ограничьте разрешения
папкой проекта. Перед эксплуатацией задайте квоту и допустимый
простой, включая время обязательной предрелизной выгрузки.

Установщик кладёт доверенный адаптер в каталог, который изменяет root.
Адаптер работает под пользователем контроллера. Команда `start` выполняется
под отдельным пользователем приложения. Приложение пишет только в каталог данных
и читает журнал допуска. Только контроллер может запускать и останавливать unit.
Команда получает `PULL_CD_DATA`,
а при запуске также `PULL_CD_REVISION` и `PULL_CD_HEALTH_URL`.

| Команда адаптера | Обязанность |
| --- | --- |
| `stage RELEASE` | Подготовить рантайм в отдельном каталоге релиза и выполнить проверку без запуска живого сервиса. Рантайм должен быть доступен на чтение группе приложения. |
| `can-stop` | Проверить состояние писателей и очередей. Код 75 откладывает операцию. Прочие ненулевые коды сигнализируют ошибку. |
| `snapshot DEST` | Создать согласованную копию данных остановленного сервиса. Первый установочный запуск также поддерживает пустой экземпляр. |
| `migrate RELEASE CANDIDATE` | Применить миграции к копии и сверить данные по правилам проекта. |
| `verify DIR` | Проверить целостность, схему и связь базы с файлами. На ПК эта команда проверяет восстановленную копию. |
| `apply DIR` | Перенести проверенный кандидат в рабочие данные. Операция должна быть повторяемой, в том числе при восстановлении исходного снимка после частичной записи. |
| `start RELEASE` | Запустить приложение через `exec` с рабочим каталогом релиза. Проверка готовности возвращает HTTP 200 с полями JSON `status` со значением `ok` и `revision`, равным `PULL_CD_REVISION`. |

Пример SQLite переносит только саму БД через SQLite Backup API.
Для записи обоими пользователями адаптер сохраняет группу каталога данных
и нужные режимы файлов. В примере SQLite рабочий файл имеет режим 0660.
Файлы, дополнительные хранилища, внешние очереди и секреты учитываются
адаптером проекта или отдельной процедурой. В первом профиле все живые
писатели должны останавливаться вместе с unit. Для существующего сервиса
переход под управление шаблона репетируют на отдельной копии его данных.

## Подключение VPS

1. Установите systemd с polkit, Python 3.12, age и rclone с поддержкой выбранного backend.
2. Создайте root-каталоги `/etc/pull-cd` и `/etc/pull-cd/<name>` с запретом записи
   для остальных пользователей. Поместите туда `github-token` с
   доступом чтения Contents и Actions одного репозитория и файл `age-recipient`
   с публичным ключом. Оба файла принадлежат root и имеют режим 0600.
   Закрытый ключ хранится у владельца вне VPS. Для rclone подготовьте отдельный
   конфиг root:root с режимом 0600 и доступом к выделенной папке проекта.
3. Из проверенного checkout выполните установку, затем один пробный деплой
   из зелёного `push` в релизную ветку. В примере имя проекта — `example`.

```sh
sudo python3 deploy/pull-cd/install.py project.json adapter.py /path/to/private/rclone.conf
sudo systemctl start pull-cd-deploy@example.service
sudo systemctl start pull-cd-backup@example.service
sudo journalctl -u pull-cd-backup@example.service -n 40
```

Скачайте подтверждённый архив из внешнего хранилища и восстановите его на ПК.
Родительский каталог должен существовать и быть доступен только оператору.

```sh
python3 deploy/pull-cd/backup.py downloaded.tar.gz.age age-identity.txt private/restore
python3 adapter.py verify private/restore
```

Успех означает валидный каталог с маркером `.restore-quarantine`.
Проверьте контрольную запись средствами проекта. После этой проверки
включите автозапуск и оба таймера.

```sh
sudo systemctl enable --now pull-cd-app@example.service pull-cd-deploy@example.timer pull-cd-backup@example.timer
systemctl list-timers 'pull-cd-*@example.timer'
```

## Откат и обслуживание

Обновление выбирается по вершине ветки, успешному push workflow и контрольным
суммам GitHub и файлов. Предрелизная копия подтверждается во внешнем хранилище
до миграции. Журнал и общий lock сохраняют однозначный порядок остановки,
снимка и запуска. После сбоя до допуска контроллер возвращает прежний релиз
и при необходимости восстанавливает исходный снимок. После допуска при
провале readiness он останавливает сервис, сохраняет текущие данные и
переводит журнал в `blocked` для оператора.

Состояние и архивы требуют свободного места на VPS и у провайдера. При
ошибке загрузки ночной снимок ждёт повторной отправки с прежним ID.
Чтобы обновить сам контроллер, остановите оба таймера, дождитесь завершения
их сервисов и фазы `idle`, запустите установщик из проверенной версии и
верните таймеры. Для `blocked` сначала сохраните текущие данные и изучите
journal. Если допустимо запустить уже допущенный код с текущими данными,
после исправления окружения используйте `resume-current`.

```sh
sudo -u pcd-example /usr/bin/python3 -B /usr/local/lib/pull-cd/example/controller.py /etc/pull-cd/example/project.json resume-current
```

На Ubuntu тест реальных systemd-таймеров, миграции, отката и восстановления
запускается с именем и портом, выделенными только для него.

```sh
sudo env PULL_CD_DRILL=1 python3 deploy/pull-cd/tests/systemd_drill.py
```

Хранилище в этом тесте — локальный backend rclone. Вход GitHub заменён
фикстурой API с реальными ZIP-артефактами. Перед эксплуатацией отдельно
проверяются push CI проекта, автодеплой с фактического GitHub и
восстановление из его реального внешнего хранилища.
